============================================================
REBUILT REVIVAL STUDIO PLAN
============================================================

WORKING APP NAME
Revival Studio

WHY THIS NAME
Revival Studio avoids confusion with the old Revival Bible AI project. It sounds like a creative workspace, not a generic AI wrapper or database utility. The app should support writing, canon, source material, chat, documents, research, brainstorming, review, and project organization.

CORE PRODUCT IDENTITY
Revival Studio is a local-first creative/editorial workspace for the Revival project.

It is not:
- a ChatGPT wrapper
- an OpenAI app
- a generic AI Studio
- a database admin tool
- a confusing all-in-one scrolling dashboard
- a hidden retrieval system
- an AI canon-mutation tool

It is:
- a Revival-only project workspace
- a place to store and organize source material
- a place to chat with Claude
- a place to save and route Claude output
- a place to manage writing, documents, brainstorming, research, questions, conflicts, decisions, and canon
- a place where AI can suggest, but the human always approves before anything is stored, routed, locked, or finalized

HARD AI RULE
No ChatGPT integration.
No OpenAI integration.
No OpenAI provider code.
No generic provider router.
No ChatGPT model picker.
No OpenAI API key fields.
No ChatGPT-branded UI.

Claude/Anthropic may be used later as the only AI provider.

AI must never silently mutate canon, decisions, tags, archived state, or stored records.
AI may suggest.
The human approves.

GLOBAL SIMPLE UI RULE
Every screen must answer:
1. Where am I?
2. What is this page for?
3. What is the main action?
4. Where will this saved thing go?
5. Can I edit, delete, archive, or restore if I made a mistake?
6. What should I do next, if anything?

Avoid:
- long confusing scroll pages
- fake future features pretending to work
- developer diagnostics in normal user flow
- hidden context
- unclear save destinations
- too many simultaneous buttons
- one-table-per-page database sprawl

============================================================
CHAT
============================================================

NAME
Chat

PURPOSE
A global Claude chat workspace available from everywhere in the app.

APP SCOPE
The app is only for the Revival project.
There are multiple chats inside this one Revival project.
There is no multi-project system.

CHAT ACCESS
Chat should be accessible globally as a right-side drawer from every workspace.
The user should also be able to expand Chat into a larger panel without replacing the whole app.
The user also wants a separate pop-out chat window later.

CHAT FEATURES
Must support:
- multiple chats inside the Revival project
- chat title dropdown
- new chat
- rename chat
- archive chat
- restore archived chat
- search chats
- persistent history
- load older history if needed
- autosaved composer draft
- clear draft
- expand chat panel
- pop-out chat window
- attach Source Material
- visible Active Sources area
- export full conversation
- highlight sections and route/export them
- Claude model selector
- model may change inside a chat
- model used should be stored per message behind the scenes

Avoid:
- forced chat categories
- confusing folders too early
- generic provider switching
- ChatGPT/OpenAI
- hidden context
- automatic database/canon mutation

CHAT ORGANIZATION
Use simple organization first:
- chat title dropdown
- search
- archive/restore
- rename
- optional pin/favorite later
- optional tags later if needed

Do not force chat type categories in MVP because one chat may include brainstorming, rewriting, canon analysis, and research.

CLAUDE MODEL HISTORY RULE
Because the app is Claude-only, do not split histories by provider.
A chat can switch Claude models if needed.
Each message should store which Claude model generated it.
The user should not have to create a new chat just to switch Claude models.

CHAT ATTACHMENTS
No Context Packets.
No Manual Context page.
No Text Context system.
No selected-excerpt attachment workflow in MVP.

For MVP, Chat attachments should support Source Material only.

ATTACHMENT MODES
Source Material attachments should support two modes:

1. Keep active in this chat
- Default for MVP.
- The source stays visibly attached until the user removes it.
- Claude can continue using it throughout the conversation.
- The app should show this in an Active Sources area.

2. Use for next message only
- Optional mode for one-off questions.
- The source is used for one message.
- Then it clears from the active attachment area.
- The chat should still record that the source was used.

Simple rule:
Attach Source Material -> choose Keep Active or Next Message Only -> send -> app visibly tracks what Claude used -> user can remove active sources anytime.

ACTIVE SOURCES UI
Chat should show an Active Sources strip/list so the user always knows what Claude is using.

Each active source should show:
- source title
- source type
- mode: Keep active / Next message only
- remove button

No hidden attachments.
No hidden retrieval.
No automatic source loading.

PROJECT RULES VS ACTIVE SOURCES
Project Rules are always-on instructions in Settings.
Active Sources are specific attached materials Claude should use for a chat.
Canon Bible is the source of locked/current truth later.
Chat history is the ongoing conversation.

EXPORT FROM CHAT
Chat should eventually support:
- export entire conversation
- export a selected message
- highlight text and export only that section
- route exported material to the appropriate destination
- AI-suggested tags/destination with human review
- no automatic final storage without user approval

Export destinations:
- Unsorted
- Documents
- Brainstorm
- Research
- Open Questions
- Conflicts
- Decisions
- Canon Review
- Copy text

NAME
Writing Lab

PURPOSE
A task-based Claude workspace.

Chat is conversational.
Writing Lab is action/task-based.

Writing Lab should help with:
- rewrite selected text
- analyze selected source
- brainstorm options
- find contradictions
- extract possible canon/review candidates
- draft scene notes

Recommended task order:
1. Rewrite selected text
2. Analyze selected source
3. Brainstorm options
4. Find contradictions
5. Extract canon/review candidates
6. Draft scene notes

WRITING LAB OUTPUT RULE

Possible actions:
- Copy
- Save to Documents
- Save to Brainstorm
- Save to Research
- Create Open Question
- Create Conflict
- Create Decision Draft
- Send to Canon Review

============================================================
CANON BIBLE
============================================================

PURPOSE
Canon Bible is the official home for locked/current Revival information.

However, the final Canon Bible structure, categories, and SQLite schema should be proposed by Claude after inspecting the finalized project knowledge files. The project knowledge files live in Claude and are evolving/finalizing there.

Do not over-prescribe the detailed Canon Bible schema before Claude inspects the files.

Canon Bible will likely include categories such as:
- Characters
- Relationships
- Worldbuilding
- Virus Master Rules
- Timeline
- Episodes / Seasons
- Locations
- Organizations
- Themes
- Mythology / supernatural rules if needed
- Style/tone rules if they are treated as canon
- Other categories Claude identifies from the actual project knowledge files

IMPORTANT CANON RULE
Locked means currently accepted, not impossible to change.
The user must be able to edit entries in Canon Bible.
Future changes to locked canon should preserve some kind of history / superseded state / decision trail where appropriate.

CANON BIBLE SHOULD SUPPORT
- active/current entries
- edit entries
- delete mistaken entries, with confirmation
- archive/retire/supersede entries
- collapsed retired/superseded section by default
- restore where appropriate
- link to source material
- link to decisions
- link to open questions/conflicts where appropriate

Canon Bible should not be finalized until the schema approval checkpoint.

UNSORTED
============================================================

PURPOSE
Unsorted is saved material that needs routing.

This replaces Creative Inbox as the simple general queue.

Definition:
Unsorted = saved material that does not clearly fit somewhere yet.

Examples:
- interesting Claude output the user does not know where to put yet
- half-formed idea
- possible note
- possible future document
- exported chat section needing sorting
- AI output with suggested destination not yet approved
- useful material that is not obviously canon/research/brainstorm/document/question/conflict/decision yet

UNSORTED ACTIONS
- Move to Documents
- Move to Brainstorm
- Move to Research
- Create Open Question
- Create Conflict
- Create Decision Draft
- Send to Canon Review
- Archive
- Delete

Unsorted should not become a confusing dumping ground. It should show simple routing actions and optional Next Step Suggestions.

AI may suggest destination/tags.
Human approves.


============================================================
CANON REVIEW
============================================================

PURPOSE
Canon Review is possible canon/project-truth material waiting for approval.

Definition:
Canon Review = material that may affect official Revival truth.

Examples:
- possible character fact
- possible worldbuilding rule
- possible virus rule
- possible timeline fact
- possible episode/season fact
- possible relationship fact
- possible source-backed canon update
- possible decision affecting Canon Bible

Canon Review is separate from Unsorted.

Reason:
Unsorted is a general routing bucket.
Canon Review is official approval work.
Canon Review needs a more careful UI with source/evidence/proposed destination.

CANON REVIEW ACTIONS
- Approve / Save As...
- Save to Canon Bible
- Create Open Question
- Create Conflict
- Create Decision
- Save to Documents
- Defer
- Reject
- Archive
- Delete mistake

AI may suggest Canon Review items, but the user must approve before they are stored.

Flow:
1. Claude suggests possible canon/review items.
2. App shows a review panel.
3. User checks/edits/approves.
4. User clicks Add to Canon Review.
5. Items are stored only after approval.

============================================================
EDIT / DELETE / ARCHIVE / RETIRED RULES
============================================================

The user wants to be able to:
- edit entries in all workspace sections, including Canon Bible
- delete entries where mistakes or typos were made
- archive entries that no longer apply
- retire/supersede entries that were overridden
- avoid a separate global archive page

RULE
Every workspace where it makes sense should have its own collapsed Archive/Retired section.

No separate Archive page.

DEFAULT LIST STRUCTURE
- Active items shown by default
- Archived/Retired/Superseded collapsed by default
- Restore option where appropriate
- Delete option with confirmation

DELETE
Use when:
- typo/test entry
- duplicate mistake
- accidental creation
- junk record

ARCHIVE
Use when:
- no longer relevant
- old but worth keeping
- retired note
- old chat
- old source material
- old brainstorm/research/document

RETIRED / SUPERSEDED
Use especially for Canon Bible and Decisions when something has been overridden but should not disappear.

Canon Bible should support:
- active/current canon
- retired/superseded canon collapsed by default
- reason for retirement/supersession where appropriate
- related decision where available

============================================================

Examples:

- Next: Analyze in Writing Lab
- Next: Send possible canon items to Canon Review
- Other: Do later

After saving Claude output:
- Next: Save to Unsorted
- Next: Save to Brainstorm
- Next: Create Open Question
- Other: Discard

After resolving a Conflict:
- Next: Create Decision
- Next: Update Canon Bible
- Next: Archive Conflict
- Other: Do later

UI rule:
Next Step Suggestions should be small and dismissible.
The user can ignore them.
They should not trap the user in a workflow.
